# Build, deployment and CSP

This document records the production build that was actually executed after
the project left the ClaudeDesign virtual filesystem. Phase 3 is complete for
the GitHub Pages frontend. The Supabase CMS client, migration 0011 and the
rebuild Edge Function are implemented locally; applying them to the user's
remote accounts remains an external release gate. Payment-provider work is a
separate, deliberately unopened gate. See `GITHUB_SUPABASE_SETUP_JA.md`.

## Authoring and production are separate

| | Authoring | Production (`dist/`) |
|---|---|---|
| Components | `*.dc.html` | compiled JavaScript |
| Template work | performed in the editor | already compiled |
| Component loading | sibling source files | static module graph |
| Third-party code | editor-provided/CDN fallback | pinned local files |
| CSP | editor requirements | `script-src 'self'` |

The `.dc.html` files remain the editable source. They, `support.js`, QA pages,
build scripts and Supabase source are never copied into `dist/`.

## Production command

```bash
npm ci
npm run build
```

`npm run build` runs, in order:

1. `build/compile-dc.mjs` — compile all 21 components.
2. `node --test build/*.test.mjs` — fixtures, real CLI, all components and the
   import graph.
3. `build/vendor.mjs` — materialise local React/ReactDOM and build the installed
   Supabase ESM graph into a CSP-safe browser IIFE.
4. `build/build-app.mjs` — prerender and assemble the application.
5. `build/bundle.mjs` — create one public and one admin entry bundle.
6. `build/verify-dist.mjs dist` — fail closed on packaging/security/SEO defects.

The current suite contains 73 tests: the original 64 compiler/graph checks plus
CMS wiring, migration, mapping, seed-safety, secret-exclusion and Storage path
checks.

The bundled build is the production path. An earlier unbundled path used an
inline import map; real-browser testing proved that `script-src 'self'` blocks
that map. The default build therefore bundles the entries and ships no import
map.

## DC compiler verification

The compiler implements only the syntax mechanically found in the 21 sources:
holes containing identifiers/dotted paths/literals, `sc-if`, `sc-for`,
`dc-import`, `<helmet>`, event/ref/value/checked attributes, inline styles and
pseudo-state styles. Unsupported or ambiguous constructs fail with a file and
line instead of being guessed.

Recorded results:

```text
21 modules compiled
47 pseudo-state rules
roots: TSUMUGI, TSUMUGI Admin
73 tests passed, 0 failed
```

The production CLI has its own regression test. This was added after the first
clean build found an out-of-scope `walk` function: the in-memory component tests
passed, but the real CLI import-graph phase failed. The fixed test now executes
`compile-dc.mjs --check` directly.

The existing differential harness also records 33 comparisons and zero
differences between the authoring and compiled runtimes. See
`shots/dc-diff-result.txt`.

## Local vendor and CSP

The shipped policy is:

```text
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
font-src 'self' https://fonts.gstatic.com;
img-src 'self' data: blob: https:;
connect-src 'self' https://*.supabase.co;
form-action 'none'; frame-ancestors 'none'; base-uri 'self'; object-src 'none'
```

`unsafe-eval` and remote script origins are absent. `unsafe-inline` remains for
styles because the design uses inline style properties and GitHub Pages cannot
issue per-response nonces.

Supabase's published webpack UMD file contained runtime global discovery that
failed the CSP gate. `build/vendor.mjs` instead builds an IIFE from the pinned
package's ESM graph. The optional OpenTelemetry import is disabled because this
application does not install or enable browser telemetry. The result is checked
for string evaluation, computed imports, remote imports and source-map markers.

## Prerendering and GitHub Pages paths

The build emits real pages for home, about, shop, journal, contact, ten seeded
products and eight seeded articles, plus `admin.html`, `404.html`, robots and a
sitemap. Public pages include unique metadata, JSON-LD and readable non-JS
content. React takes over the same URL from `<meta name="dc-route">`.

Known pages use depth-relative assets and work at a domain root or repository
subpath. GitHub Pages serves `404.html` at the unknown URL itself, so relative
assets cannot work there. The 404 page uses the explicit deployment base from
`BASE_PATH`, or derives it from `SITE_URL`:

```bash
SITE_URL=https://<user>.github.io/<repo> npm run build
# equivalent explicit form:
BASE_PATH=/<repo>/ SITE_URL=https://<user>.github.io/<repo> npm run build
```

For a custom domain at its root, use its root URL. Publish `dist/`, not the
repository root.

## Release gate

`npm run verify` rejects, among other things:

- runtime compilation/evaluation, weak CSP and remote/computed module imports;
- authoring files or editor runtime references in `dist/`;
- missing bundle, local vendor file, pseudo stylesheet or shared script;
- inline import maps that the page CSP would block;
- asset references that do not resolve inside the deployment;
- root-absolute paths outside the declared 404 deployment base;
- missing/duplicate metadata, JSON-LD, favicon, sitemap or readable body;
- `.dc.html`, source maps, debug output and browser-visible secret markers.

Recorded final result:

```text
verify: 51 files, 25 HTML pages, 23 unique titles,
        23 unique descriptions, bundled application
verify: no banned strings, metadata complete and unique,
        subpath-safe — build accepted
```

`npm audit` reports zero vulnerabilities.

## Real-browser verification

Only `dist/` was served. The following eight routes were tested at 390, 768 and
1440 px (24 cases):

```text
/
/shop/
/about/
/journal/
/contact/
/p/1/
/a/august-arrivals-2026/
/admin.html
```

Every case mounted one React root, loaded one local bundle, contained no import
map, made no remote script request, logged zero console warnings/errors and had
no horizontal overflow. `/shop/` also passed a direct reload. The article title
was checked after React takeover to ensure the site suffix appears once.

A separate `/repo/` deployment tested the root, shop, admin and the deep unknown
URL `/repo/missing/deep/path`. The custom 404 response loaded its bundle and
pseudo stylesheet from `/repo/`; console and overflow remained clean.

## What ships

Publish only:

```text
dist/**
```

Do not publish `node_modules/`, `shots/`, `supabase/`, `build/`, `generated/`,
`*.dc.html`, `support.js` or Markdown documentation. `auth-config.js` may contain
only the publishable Supabase browser key. Never put a privileged server or
secret key in a GitHub Pages file.

## Remaining release gates outside Phase 3

The frontend production build is complete, but live commerce is not approved
until all of the following are executed in the target environment:

- migrations `0001`–`0011` applied in order;
- `supabase/tests/rls_matrix.sql` passes after a database reset;
- Edge Functions tested with invalid JWTs, rate limiting, idempotency and
  concurrent orders;
- staff revocation verified against an old token;
- Supabase redirect URLs and allowed origins configured;
- at least one real staff role provisioned;
- payment provider connected and end-to-end order/payment reconciliation tested.

Therefore:

- GitHub Pages frontend demo: allowed after setting the real `SITE_URL`.
- Real customer data: not yet allowed.
- Real order/payment acceptance: not yet allowed.
