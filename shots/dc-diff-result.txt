WHAT THIS IS
Both runtimes render the same application at the same route in the same
viewport, and the resulting DOM is compared node by node: tag order, text,
attributes, ARIA, inline style declarations, live value/checked/disabled.
Normalised away (each an intended difference between the runtimes, not a
defect being hidden): the .sc-interp span the authoring runtime wraps every
resolved hole in, the display:contents wrapper it puts around each child
mount, classes beginning "sc", data-dc-tpl / data-sc-name / data-dc-line, and
the digits in React-generated ids. Everything else is compared exactly.

THREE HARNESS DEFECTS FOUND AND FIXED WHILE GETTING HERE
Recorded because each produced a red result that was NOT a compiler fault, and
a reader should know the green above was not obtained by loosening the test:

1. Admin routes. The console namespaces every screen under #/admin/... — the
   first version navigated to #/orders, which routes nowhere, so four "console
   screen" comparisons were silently comparing the dashboard with itself
   (identical 436-node counts gave it away). Fixed: real routes, and the node
   counts now differ per screen (110 / 531 / 435 / 345 / 177).

2. Guest-lock race. The console's read-only lock is imperative DOM work driven
   by a debounced MutationObserver, landing 600–1000 ms after render. The two
   frames were navigated one after the other, so one was sampled before its
   lock and one after — reporting a difference that reversed polarity depending
   on which frame won. Measured on both runtimes: identical convergence, 1/36
   disabled at 300 ms rising to 24/36 by ~1 s on each. Fixed: both frames
   navigate together, then wait on the lock itself (awaitGuestLock) rather than
   on a timer.

3. Hero rotation. The home hero advances every 7 s, so frames mounted seconds
   apart sat on different slides. Fixed: both driven to slide 01 before
   comparing.

WHAT THIS DOES NOT COVER
· The compiled side resolves react / react-dom / @supabase/supabase-js through
  an esm.sh import map, because vendor/ requires npm and npm is not available
  here. The shipped shells point the same three specifiers at local files. The
  library CODE is therefore the same; its ORIGIN is not what production uses.
· Post-authentication admin states beyond the guest role. Guest is the only
  session obtainable without a live Supabase project.
· Order placement, contact submission and anything else that requires the Edge
  Functions, which have never been deployed.
